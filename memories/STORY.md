# Ciment Collections — story
Internal collections app for Ciment's bookkeeping team (3 bookkeepers + collections manager). Deterministic code does the work, agents read and sort, people approve/adjust/ask. Production app; deep discovery with the client is still pending (a demo + discovery talk with Yaniv so far).

## Structure
Three mini-apps (the platform refuses "/" as a mini-app once there are two):
- **/collections (גבייה):** the team's workspace for everyone signed in. "/" and old top-level addresses redirect under /collections. Menu since 28.10: היום · תקבולים · פניות · דוח גיול · לקוחות (360 card /collections/customers/[code], tabs incl. קבלות and אובליגו וביטוח ?tab=credit) · הגדרות, plus the build pages. Removed from the menu: הבטחות, חשבוניות (promises are aging notes; invoices are a card tab), אישורים and מסמכים ומחירים (28.10, now inside פניות), the insurance screen (deleted 27.10). Blocked orders stay off the menu.
- **/collections/inbox (פניות, component 04, 28.10):** 3 tabs ?tab=inbox|outbox|automations; folders ?folder=all|1..5|other; filters ?state/mailbox/bookkeeper/customer; mail panel ?email=; outbox ?status/component/batch/draft. Redirects: /collections/approvals → ?tab=outbox, /collections/disputes → folder=3 (?tab=prices → folder=4), /collections/inbox/open-debts → ?tab=automations. Case pages /collections/disputes/[disputeId] stay, opened from the panel.
- **/collections/settings:** tabs כללים (AgentSettings with basis tags; openDebtsDay hidden) · תפקידים (?tab=roles: sales agents + authorised customers, logistics per product line, team phones) · ייבוא קבצים.
- **Build-stage pages (not for production)** behind SHOW_BUILD_PAGES (src/utils/buildPages.ts): פערים (/collections/gaps, tabs receipts/aging/credit/sync/inbox) and Design (/collections/design: 01–04 with מסמך/דיאגרמה, cross tabs סנכרון, סוכנים, נתונים (DB), תוכנית). Sources are memories/files/*.md copied verbatim into src/utils/buildDocs/*.ts; designDb.ts and plan.ts are generated (`pnpm gen:db-doc`, `pnpm gen:plan-doc`).
- **/nina:** Nina's mini-app (CollectionsAgent), receipts only. **/maya:** Maya's mini-app (CollectionsInboxAgent), opens on a new chat; own page /maya/inbox linking to /collections/inbox?email=. "שאל את…" chats: AskNinaChat on receipts, AskMayaChat in the mail panel (questions only).
- /nora and Nora (AgingAgent) were removed on 26.10; briefings history at /collections/briefings.
- No app roles; "שלי / של כולם" is only a filter. Priority mirrors are read-only; every state change goes through actions.

## Decisions
- Deterministic code actions do the work; AI only reads (bank file, remittance mails, inbound-mail sorting) in a fixed structured answer with quotes the code verifies. Every Priority write is a proposal ("אושר – לביצוע ב-Priority" → a human marks "בוצע"). Nothing is sent: every outbound item is an Approvals draft that stops at "אושר – לא נשלח".
- Working rules from Saar: Saar runs all tests (I and subagents don't); every change also updates Design, Gaps and the plan (memories/files/BUILDER_PLAN-full.md → plan.ts); big builds are split one stage per turn (interrupted turns lose everything — happened in iterations 5, 8a, aging round 2, 04).
- Test data, never "mock": TEST-001..015, mirrors source=test-fixture, app tables isTestFixture=true, names "בדיקה – ". SeedTestFixtures (`tables` for partial reloads, dryRun defaults true) / DeleteTestFixtures. Seeded inbound mails go through the real ProcessInboundEmail (slow: up to ~60 s per mail).
- Login: private app, platform login (Hebrew login would need a public app).
- Design: Liquid+ (memories/files/DESIGN.md) binding app-wide, except the aging report, which since 27.10 has Saar's own approved look (solid white cards, concrete #F4F6F8, cobalt, argyle header, scoped --ag-* tokens, utils/AgingStyle.ts, components/aging/AgingCards.tsx) — never undo it. Saar prefers tables, calm background, blue that doesn't dominate. No asset files under src/ (git import skips them).
- Roadmap: a second Ciment app (orders/coordination/distribution) on Priority, sharing data via app Dependencies; the final build happens in the client's own Blocks account.
- Never request Linear (removed 21.10).
